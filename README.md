# TestQuest — автотесты калькулятора смет

Автор: **@master4bug**.

Проект проверяет `https://testquest.pryaniky.com/`, раздел **Продажи → Калькулятор смет**, без запуска тяжёлого браузера.

## Что проверяется

- качество и читаемость итогового Excel;
- метаданные коммерческого предложения в Excel;
- тарифы «Облако» и «Коробка»;
- количество пользователей и срок лицензии;
- модули и итог в Excel;
- работы по внедрению в Excel;
- Time&Material в Excel;
- валидация числовых полей;
- отсутствие явных ошибок формул и повреждённых значений;
- переходы в соседние разделы документов.

Всего автоматизировано 10 сценариев. Проверяются интерфейсный контракт, код расчёта/экспорта и встроенный Excel-шаблон. Ручные шаги и ожидаемые результаты описаны в `TEST_CASES.md`.

## Требования

- Windows, Linux или macOS;
- Node.js 20 или новее;
- доступ в интернет.

Устанавливать npm-пакеты вручную не нужно: это делают скрипты запуска. Chromium и системные графические библиотеки не требуются.

Зависимости находятся в разделе `dependencies`, потому что песочница запускается в production-режиме и не устанавливает `devDependencies`.

Linux-скрипт поддерживает окружения, где бинарный файл называется `nodejs`, и запускает npm через найденный путь к Node.js. Это важно для изолированной песочницы TestQuest.

Цены на стенде синтетические, поэтому тесты не привязаны к конкретным суммам. Проверяется перенос выбранной конфигурации в Excel, наличие итогов и отсутствие ошибок в книге.

## Запуск в Linux или macOS

```bash
chmod +x run-tests.sh
BASE_URL=https://testquest.pryaniky.com ./run-tests.sh
```

## Запуск в Windows

```bat
set BASE_URL=https://testquest.pryaniky.com
run-tests.bat
```

Если `BASE_URL` не задан, используется `https://testquest.pryaniky.com`.

## Как понять результат

Во время запуска выводится результат каждого теста. Последняя строка:

- `PASSED` — все тесты прошли, код выхода `0`;
- `FAILED` — есть ошибка, код выхода отличается от `0`.

## Структура

```text
.
├── README.md
├── ANALYSIS.md
├── TEST_CASES.md
├── package.json
├── run-tests.bat
├── run-tests.sh
└── tests
    └── calculator.test.txt
```

Песочница запрещает хранить в ZIP исполняемые файлы `.js/.cjs`. Поэтому исходник JavaScript лежит в `tests/calculator.test.txt`. Скрипт запуска создаёт временную копию `.js` после распаковки и запускает её встроенным тест-раннером Node.js.

Код намеренно сделан простым: один файл тестов, две небольшие вспомогательные функции и понятные селекторы.
