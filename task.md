# Тестовое задание: TestQuest — Калькулятор смет

## Цель задания

Проверить полный цикл работы раздела «Продажи → Калькулятор смет» на стенде:

`https://testquest.pryaniky.com/`

Нужно проверить метаданные коммерческого предложения, тарифы «Облако» и
«Коробка», количество пользователей, срок лицензии, модули, внедрение, T&M,
итоговую сумму, выгрузку Excel и валидацию результата.

Минимальные требования:

- описать не менее 10 тест-кейсов;
- автоматизировать не менее 7 тест-кейсов;
- подготовить запуск для Linux и Windows;
- устанавливать зависимости автоматически;
- выводить итог `PASSED` или `FAILED`;
- возвращать корректный код завершения;
- обеспечить запуск в изолированной песочнице.

## Выбранное решение

Проект написан на JavaScript. Для запуска тестов используется встроенный в
Node.js модуль `node:test`, а для чтения Excel — библиотека `xlsx`.

Браузерная автоматизация намеренно не используется. Песочница не содержит
системных библиотек Chromium, а загрузка браузера увеличивает время запуска и
может привести к ошибке HTTP 504.

Тесты проверяют реальные ресурсы приложения, связь полей калькулятора с кодом
расчёта и экспорта, а также встроенный Excel-шаблон итоговой сметы.

## Этапы выполнения

### 1. Анализ приложения

- изучена главная страница стенда;
- определены JavaScript-файлы расчёта и экспорта;
- найден встроенный Excel-шаблон;
- выделены основные функциональные блоки калькулятора;
- учтена подсказка, что синтетические цены не нужно сравнивать с фиксированными
  значениями — важнее качество итоговой сметы.

### 2. Проектирование проверок

Подготовлены 10 тест-кейсов для следующих областей:

1. доступность калькулятора;
2. метаданные коммерческого предложения;
3. тарифы «Облако» и «Коробка»;
4. количество пользователей и срок лицензии;
5. модули;
6. внедрение;
7. T&M;
8. выгрузка Excel;
9. структура и оформление Excel;
10. отсутствие явных ошибок в Excel и коде экспорта.

### 3. Реализация

- создан простой тестовый файл `tests/calculator.test.txt`;
- расширение `.txt` используется из-за запрета песочницы на JavaScript-файлы
  внутри загружаемого архива;
- `run-tests.sh` и `run-tests.bat` создают временную копию с расширением `.js`;
- зависимости устанавливаются автоматически командой `npm install`;
- запросы к стенду выполняются встроенной функцией `fetch`;
- Excel-шаблон декодируется из Base64 и открывается библиотекой `xlsx`.

### 4. Проверка Excel

Автотесты подтверждают, что:

- книга открывается без повреждений;
- присутствует хотя бы один непустой лист;
- в книге есть содержимое и признаки оформления;
- отсутствуют `#REF!`, `#VALUE!`, `#DIV/0!`, `NaN` и `undefined`;
- ключевые поля калькулятора не потеряны в экспортном контуре.

### 5. Адаптация под песочницу

Первый браузерный вариант потребовал загрузки Chromium и завершился ошибкой
из-за отсутствующих Linux-библиотек. Решение было упрощено и переведено на
проверку HTTP-ресурсов и Excel без запуска браузера.

Также была устранена нестабильная проверка конкретного HTML-идентификатора
модуля. Карточки модулей создаются динамически, поэтому проверка выполняется по
данным приложения и связи модулей с расчётом и экспортом.

## Запуск

Linux/macOS:

```bash
BASE_URL=https://testquest.pryaniky.com ./run-tests.sh
```

Windows:

```bat
set BASE_URL=https://testquest.pryaniky.com
run-tests.bat
```

## Результат

Финальный запуск в официальной песочнице:

```text
tests: 10
pass: 10
fail: 0
exit code: 0
PASSED
```

Все проверки прошли за 2,1 секунды.
